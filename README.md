# Каталог знижок — автоматичний

Каталог знижок 4 київських супермаркетів (Сільпо, Novus, Фора, АТБ) із РЕАЛЬНИМИ
фото товарів, порівнянням цін між магазинами і підсвіченням найдешевшого варіанту.

## Як це працює тепер

Каталог оновлюється **сам, щосуботи, без участі людини** — через GitHub Actions
(`.github/workflows/update-catalog.yml`). Робочий процес:

1. GitHub щосуботи о 06:00 UTC (~09:00 Київ) запускає віртуальну машину;
2. вона виконує `node scrape.js && node build.js` (реальний headless Chromium,
   реальні фото з сайтів магазинів);
3. новий `catalog.html` (і копія як `index.html`) та накопичена бібліотека фото
   в `images/` автоматично комітяться назад у репозиторій;
4. GitHub Pages роздає `index.html` за постійною адресою — просто відкривай її
   в браузері раз на тиждень, нічого запускати не треба.

Чому саме субота: живим запуском (16.08.2026) перевірено, коли кожен магазин
насправді оновлює тижневі знижки — АТБ у середу, Сільпо й Novus у четвер, а
Фора найпізніше — у п'ятницю (докладніше в коментарі над cron-рядком у
workflow-файлі). Субота — із запасом після найпізнішого з чотирьох, щоб жоден
магазин не потрапив у каталог зі знижками ще минулого тижня.

Адреса сайту: `https://<твій-github-логін>.github.io/<назва-репозиторію>/`
(з'явиться після першого пушу — GitHub Pages вмикається окремим кроком, дивись нижче).

Щоб оновити каталог позапланово (не чекаючи суботи) — на сторінці репозиторію
на GitHub: вкладка **Actions** → **Update discount catalog** → **Run workflow**.

## Список покупок

Біля ціни кожного товару є кнопка «+» — додає товар у список покупок ТОГО
магазину (не всього товару загалом, бо купуєш в одному конкретному місці).
Внизу з'являється плаваюча кнопка з лічильниками по магазинах — відкриває
список із чотирма вкладками (Сільпо/АТБ/Novus/Фора), сумою по кожному й
чекбоксом "взято" для відмітки під час самого шопінгу.

Список зберігається в `localStorage` браузера — працює лише на тому пристрої,
де його складали (без бекенду й акаунтів). Якщо відкрити каталог після того,
як п'ятничний автозапуск перезібрав сторінку наново, з'явиться попередження
"список зі старої дати" з вибором лишити його чи почати новий — самі товари
за тиждень могли зникнути з акцій.

## Локальний запуск (для тестів/налагодження)

Не обов'язковий для щотижневого використання — лише якщо хочеш щось налагодити
на своєму комп'ютері.

```bash
npm install
npm run install-browser   # якщо ще не робив: playwright install chromium
npm run all               # node scrape.js && node build.js
```

Окремо:

```bash
node scrape.js            # тільки збір даних + фото
node scrape.js silpo atb  # тільки ці два магазини (швидше, для тесту)
node scrape.js --debug    # видиме вікно браузера + html/screenshot в debug/
node build.js             # тільки перезбірка HTML з уже наявних data/
```

## Структура проєкту

- `scrape.js` — відкриває Сільпо/АТБ/Novus/Фора в справжньому Chromium (Playwright),
  для кожного магазину використовує СВІЙ екстрактор під живу верстку сайту (не
  універсальна евристика — вона виявилась занадто крихкою для 4 різних сайтів),
  качає фото в `images/`, пише сирі дані в `data/`.
- `build.js` — читає `data/`, виключає нехарчові/алкогольні хибні збіги, розкладає
  товари по 20 категоріях, групує однакові товари з різних магазинів для порівняння
  ціни, збирає фінальний `catalog.html`.
- `config.js` — усі налаштування: сторінки для кожного магазину, категорії й ключові
  слова, виключення. Можна редагувати як завгодно.
- `.github/workflows/update-catalog.yml` — щотижневий автозапуск.

## Технічні деталі про кожен магазин (на майбутнє, якщо сайт зміниться)

Усі 4 сайти перевірені живим запуском (не наосліп) — ось що з'ясувалось:

- **Сільпо й АТБ стоять за Cloudflare.** Перша сторінка в межах сесії відкривається
  нормально, але кожна НАСТУПНА навігація в тій самій сесії (той самий browser
  context/cookies) майже одразу ловить антибот-заглушку ("Just a moment…" /
  "Трохи зачекайте…" — Cloudflare Turnstile), навіть з паузами по 7-10с між
  запитами. Рішення, яке реально працює: **окремий browser context на кожну
  сторінку** (уже реалізовано в `scrape.js`).
- **АТБ** додатково показує модалку підтвердження 18+, яка блокує сторінку —
  `scrape.js` автоматично її закриває.
- **Сільпо**: чіткі Angular-класи `.product-card`, `.product-card__title`,
  `.product-card-price__displayPrice` / `__displayOldPrice`.
- **Novus**: стандартна Magento-верстка, `li.product-item`, ціни через атрибути
  `data-price-type="finalPrice"/"oldPrice"` на `[data-price-amount]`.
- **Фора** (найризикованіше місце за первісною гіпотезою) виявилась цілком
  скрейпабельною: `.product-list-item`, `.product-title`, ціна складається з
  `.current-integer` + `.current-fraction`; пагінація — звичайний query-параметр
  `?to=N&from=N`, не лише "показати ще" по кліку.

Якщо якийсь сайт колись змінить верстку — дивись `debug/` (запусти
`node scrape.js <store> --debug`) і онови відповідний екстрактор у
`STORE_EXTRACTORS` (`scrape.js`).

## Категорії й виключення

Список із 19 основних категорій та ключових слів — у `config.js` (`CATEGORIES`).
Товари в категорії сортуються АЛФАВІТНО за назвою (не за розміром знижки) —
українські назви завжди починаються з базового слова товару ("Йогурт...",
"Сир..."), тому такий порядок групує однотипні товари поруч, зручно гортати
"всі йогурти підряд", а не бачити їх розкиданими по картках залежно від
знижки цього тижня.

Товар, що не підійшов під жодну з 19, перевіряється ще раз проти
`EXTRA_CATEGORIES` (до 7 додаткових категорій — зараз 5: Вино, Пиво та сидр,
Яйця, Одяг/взуття/аксесуари, Догляд та побутова хімія). "Яйця" винесено сюди
з основних 19 за проханням Лери — не окрема категорія в головному списку.
Це реальні великі кластери товарів, які магазини домішують у ті самі сторінки
знижок, але які не входять у харчові категорії Лери. Показуються окремою
секцією внизу сторінки (за роздільником "Інші категорії"), не змішуючись з
основним списком. Те, що не підійшло взагалі нікуди (новорічний декор,
іграшки, канцтовари, батарейки, дитячі товари тощо) — свідомо не
показується; кількість видно в консолі після `node build.js`.

Товари типу "чипси зі смаком курки", "приправа до курки", "круасан з
сосискою", "суп зі смаком бекону" — тобто де м'ясне/сирне слово це насправді
СМАК чи інгредієнт готової страви/снеку, а не сам продукт — не потрапляють
у м'ясні/сирні категорії (`PROTEIN_EXCLUDE` у `config.js`, застосовується до
cheese/sausage/fish/poultry). Список побудований на реальних знахідках, а не
навмання — якщо колись знову побачиш булочку чи готову страву в м'ясі/сирах,
шукай нове ключове слово-смак і додавай його туди ж.

`EXCLUDE_KEYWORDS` виключає мелену/розчинну каву, корм для тварин, дитячі
товари (за проханням Лери), побутову хімію/косметику, що трапляється в тих
самих сторінках знижок і випадково ловить харчові ключові слова через
запах/смак у назві (бо трапляються ті самі слова-аромати: "лимон", "фрукт"
тощо), і міцний алкоголь (горілка, коньяк, віскі тощо — українські виробники
офіційно пишуть "напій алкогольний на основі рому/віскі", без цього списку
горілка й ром потрапляли б у "Безалкогольні напої"). Звичайні вино/пиво не
виключаються — вони йдуть у відповідні `EXTRA_CATEGORIES`.

Ключові слова з пробілом на кінці (напр. `"чай "`, `"бри "`) означають "ціле слово",
а не основу — це важливо, бо просте `includes()` без перевірки меж слова false-positive
ловить, наприклад, `"бри"` всередині `"мікрофібри"`, або `"вівс"` всередині
`"Львівське"`. Функція `hasKeyword` у `build.js` це враховує (завжди перевіряє
межу зліва; межу справа — лише коли ключове слово написане з пробілом).

Деякі категорії (напр. "Безалкогольні пиво/сидр/вино") використовують
`keywordGroups` — товар підходить, якщо містить УСІ слова хоч однієї AND-групи,
навіть не поруч. Це критично: в реальних назвах "Пиво Bitburger Drive світле
безалкогольне" слова "пиво" і "безалкогольне" стоять на різних кінцях назви,
і проста фраза-підрядок "безалкогольне пиво" НІКОЛИ б їх не впіймала.

Групування "той самий товар у різних магазинах" — евристика за збігом слів у назві
(поріг Жаккара 0.4), у `build.js`, функція `groupCategory`. Не ідеальна, але для
щотижневого огляду цілком робоча; помилки групування видно одразу в самому каталозі.

## Ціна за вагу (кг/100г) — коли й чому вона показана

Живим тестуванням (16.08.2026) з'ясовано, що Сільпо показує ціну свіжого
м'яса/риби/сиру НА ВАГУ за 100г, ніде прямо цього не підписуючи (той самий
текст "100г" виглядає як вага пакунка) — тобто "18.4 ₴" на курячому філе
насправді означає ціну ЗА 100Г, а не за кг чи за штуку (реальна ціна за кг —
у ~10 разів більша). АТБ, Novus і Фора цю одиницю виміру показують явно у
себе в HTML (`/кг`, "за 1 кг", голе "кг"/"г" у назві ваги), просто ми це
раніше не витягували.

Тому `scrape.js` тепер зберігає поле `unit` (там, де магазин взагалі показує
одиницю виміру), а `build.js` дописує його одразу біля ціни — `59.99 ₴/150г`
замість голого `59.99 ₴`. Для Сільпо це показується ЗАВЖДИ (бо немає способу
надійно відрізнити "вага пакунка" від "розрахункова одиниця для вагового
товару" — обидва виглядають однаково в їхньому HTML), для АТБ/Novus/Фора —
лише коли товар справді ваговий (кг/г), не для звичайних штучних товарів.

## Мобільний вигляд: 2 картки в ряд

На екранах до 640px `.grid` — 2 колонки замість 1 (медіа-запит у `build.js`),
з дрібнішим текстом і компактнішими відступами — фото лишається головним
елементом картки, а не назва товару чи ціна. Мета: щонайменше 4 товари
видно одразу на екрані без нескінченного скролу вниз.

## Фото накопичуються, а не перекачуються щоразу

`scrape.js` перевіряє, чи фото з такою назвою (slug + hash URL) уже є на диску —
якщо так, повторно не качає. Оскільки CI-запуск щоразу починається з чистого
checkout репозиторію, а не з локального диска, кеш працює лише тому, що `images/`
і `data/` **комітяться назад у репозиторій** після кожного запуску (дивись workflow).
Не видаляй ці папки з репозиторію — це і є "бібліотека фото".
